# Архитектура

Godot 4.4, GDScript. Слои по ТЗ §4:

| Слой | Папка | Что внутри |
|---|---|---|
| Domain / Data | `src/wardrobe`, `src/economy`, `src/save`, `src/core/story_flags.gd`, `data/` | Правила и состояние, без зависимостей от сцен. Всё покрыто тестами |
| Gameplay | `src/gameplay` (будет) | Управление, камера, взаимодействия |
| Presentation | `src/ui`, `src/visual`, `scenes/` | Экраны, иконки, визуальные заглушки |
| Platform | `src/core/game.gd` | Автозагрузка, сохранение на диск, масштаб UI |

## Корень сборки
`GameSession` (`src/core/game_session.gd`) загружает данные из `data/` и связывает сервисы.
Используется и игрой (через автозагрузку `Game`), и тестами — без сцен.

```
GameSession
├─ WardrobeConfig        справочники и коэффициенты (data/wardrobe/config.json)
├─ ItemCatalog           каталог одежды + валидация (items.json)
├─ CharacterCatalog      персонажи, типы тела, фирменные образы (characters.json)
├─ FashionChallengeCatalog  испытания + проверка наград (challenges.json)
├─ WardrobeInventory     общий гардероб: факт владения
├─ ResourceInventory     валюта и материалы, транзакционно, с лимитами
├─ CharacterEquipment    образ каждого персонажа (Outfit), слоты, совместимость
├─ OutfitPresetManager   сохранённые комплекты
├─ FashionScoringService детерминированная оценка + отчёт
├─ FashionAdvisor        советы: какие свои вещи поднимут оценку
├─ ItemGrantService      единая выдача предметов и правило дубликатов
├─ CraftingService       выкройки и крафт (атомарно)
├─ ShopService           магазины (атомарно, лимиты)
├─ ChallengeRewardService результаты и награды без повторной выдачи
└─ StoryFlags            сюжетные флаги
```

## Ключевые решения
- **Черновик примерки.** UI меняет копию `Outfit`; в `CharacterEquipment` она попадает только по кнопке «Сохранить».
- **Формула оценки** (ТЗ одежды §9): `Final = round((Σ base·theme·item_mult + синергии + бонусы) · Q)`.
  Правила темы проверяются в порядке данных, первое совпадение побеждает. Штрафы объединяются методом
  `strictest` (или `bounded_product` с нижней границей) — порядок проверки не влияет на итог.
  Штраф «тема проигнорирована» применяется, только если испытание задаёт тематические правила.
- **Дубликаты** при любой выдаче конвертируются в монеты по редкости (`duplicate_policy`); если лимит монет
  достигнут — дубликат игнорируется, а не «конвертируется в никуда».
- **Крафт уже имеющейся уникальной вещи** запрещён, чтобы не тратить материалы впустую.
- **Сохранения** — JSON в `user://`, версия схемы, явные миграции (`SaveMigrations`), запись через `.tmp`
  и резервная копия `.bak`. Неизвестные ID не ломают загрузку и хранятся в `orphaned_items`;
  если предмет вернётся в каталог, он вернётся и в гардероб.
- **Локализация** — `data/localization/<locale>.json` загружаются в `TranslationServer` при старте.

## Интерфейс
См. `docs/UI_STYLE.md`. Экран гардероба — `scenes/ui/wardrobe.tscn` (`WardrobeScreen`), состоит из
переиспользуемых частей: `Sheet` (всплывающее окно), `ItemCard`, `ChallengePanel`, `ItemDetails`,
`ResultPopup`, `PresetsPanel`, `IconView`/`Icons`, `RankBadge`, `AvatarView`, `SoftBackground`.
UI не считает очки и не проверяет совместимость сам — только вызывает сервисы.

## Визуальная заглушка
`PlaceholderAppearance` — манекен из примитивов, показывает слоты, цвета вещей и рост персонажа.
Это **не** финальная визуальная система: нужны модели, риг и точки крепления (`docs/ART_PIPELINE.md`).
